# 차량 선택 목록 중앙 정렬 구현 계획

## 목표와 원인

공통 `VehicleSelectionCard`가 부모의 실제 가용 너비 안에서 차량 목록을
중앙 정렬하도록 한다. 적용 화면은 홈과 라이더 만들기의 기본/사용자 이미지 모드다.

iPhone 11 Pro 세로 폭 375pt에서 화면 좌우 여백 40pt, 카드 내부 여백 24pt를
빼면 목록 너비는 311pt다. 일반 모드 버튼 최소 크기 72pt와 간격 8pt 때문에
4열은 312pt가 필요해 3열로 줄어든다. 부모 Column의 왼쪽 정렬과 Wrap의
내용 너비 축소 때문에 3열 너비 232pt 밖의 나머지 79pt가 오른쪽에 남는다.

## 구현 — 한 커밋

제안 메시지: `fix(ui): center vehicle choices within available width`

파일:
- `lib/widgets/vehicle_selection_card.dart`
- `test/vehicle_selection_card_test.dart`

변경:
- LayoutBuilder가 반환하는 기존 Wrap을
  `SizedBox(width: constraints.maxWidth, child: Wrap(...))`로 감싼다.
- Wrap의 `alignment: WrapAlignment.center`가 카드 내부 전체 너비에서 작동한다.
- 버튼 크기, 일반 모드 72~84pt 제한, compact 계산, 간격, 순서, 잠금,
  선택 표시, 미리보기와 콜백은 기존 동작을 유지한다.
- 열 수를 고정하지 않는다. 큰 화면의 4열 초과 배치와 마지막 부분 행도
  기존 자동 줄바꿈 규칙을 유지하면서 중앙 정렬한다.

위험: 낮음. 공통 위젯이므로 홈의 compact 모드와 라이더 만들기의 일반 모드를
함께 검증한다. 변경한 래퍼와 회귀 테스트를 한 커밋으로 되돌릴 수 있다.

## 검증 계획

1. 현재 구현에 375pt 일반 모드의 행 중앙 정렬 테스트를 추가해 실패를 확인한다.
2. 테스트에서는 화면 폭에서 좌우 20pt를 뺀 카드 너비를 실제로 제한한다.
   버튼의 존재나 래퍼 형태만 확인하지 않고 렌더링된 사각형 좌표를 비교한다.
3. 화면 폭 320/375/376/390/430/768pt를 검증한다. 각 행의 버튼들을 y좌표로
   묶고, 행의 좌우 끝 중점이 카드 내부 중앙과 0.5pt 이내로 일치하는지 확인한다.
   모든 버튼이 카드 내부 범위에 들어오고 레이아웃 예외가 없는지도 확인한다.
4. 일반 모드에서 375pt의 3열×4행, 376pt의 4열×3행과 72pt 버튼을 확인한다.
   768pt에서는 7개/5개 행의 중앙 정렬을 확인한다.
   compact 모드에서는 기존 4열 배치와 크기 계산을 확인한다.
5. 기존 잠금/해제 차량의 탭 콜백 테스트를 유지한다.
6. 구현 파일과 테스트 파일 format, `flutter analyze --no-pub` 실행 후
   아래 관련 테스트를 실행한다.

```sh
flutter test --no-pub test/vehicle_selection_card_test.dart test/avatar_setup_screen_test.dart test/home_screen_test.dart test/home_vehicle_entitlement_test.dart
```

UI 레이아웃 수정에 대한 기본 검증은 위 범위로 한다. 네이티브 또는 Release
문제가 확인되지 않으면 Xcode 빌드를 추가로 실행하지 않는다.

  검증 결과 보고. 구현 승인을 받은 후 작업하며 커밋은 별도 지시에 따른다.

기존 iOS 프로젝트 사용자 변경은 보존한다. 리소스, 의존성, 네이티브 설정은
이번 수정 범위에 포함하지 않는다.

## 구현 결과

- 공통 Wrap에 가용 너비를 지정하는 SizedBox를 적용했다.
- 수정 전 375pt 일반 모드 테스트가 실패했다: 행 중심 148pt,
  카드 중앙 187.5pt로 왼쪽 편차 39.5pt를 재현했다.
- 6개 화면 폭 × 일반/compact 모드의 12개 좌표 회귀 테스트를 추가했다.
  375/376pt 열 전환, 큰 화면의 마지막 부분 행, 버튼 범위와 기존 잠금 탭도 검증했다.
- 관련 4개 테스트 파일의 53개 테스트 통과. `flutter analyze --no-pub` 문제 없음.
  변경 파일 format과 diff 공백 검사도 완료했다.
- Xcode 빌드와 커밋은 수행하지 않았다. iPhone 실기기 수동 확인은 남아 있다.

## 추가 요청 반영 — 2026-10-06

사용자가 차량 버튼 양옆의 빈 공간을 없애고 모든 화면 크기에 유연하게 대응하도록
요청했다. 이전의 버튼 크기 유지 정책을 아래 방식으로 보완했다.

- 부모의 실제 가용 너비와 선호 버튼 크기로 열 수를 정한 뒤,
  간격 8pt를 제외한 너비를 버튼들이 균등하게 나눠 사용한다.
- 일반 모드의 72~84pt는 열 수 선택 기준이며 최종 버튼 크기의 제한이 아니다.
  375pt 화면에서는 3열을 유지하고 버튼 크기가 72pt에서 약 98.33pt로 커진다.
- compact 모드는 최대 4열이며 공간이 부족하면 48pt 기준으로 열 수를 줄인다.
  넓은 화면에서 차량 수가 부족한 마지막 부분 행은 같은 버튼 크기로 중앙 정렬한다.
- 전체 목록 높이가 화면보다 크면 호출 화면의 기존 스크롤로 접근할 수 있다.
- 폭 200/240/280/320/375/376/390/430/768/812/1024pt의 두 모드와
  실행 중 375×812 ↔ 812×375 회전을 검증했다. 완전한 행의 좌우 끝 좌표가
  카드 내부 여백 경계와 일치하고 모든 버튼이 카드 안에 들어오는지 확인했다.
- 관련 4개 테스트 파일의 65개 테스트 통과, 정적 분석 문제 없음.
  format과 diff 공백 검사 완료. 추가 Xcode 빌드·커밋은 수행하지 않았다.
- 사용자 수동 확인: iPhone 11 Pro 세로/가로에서 홈 및 라이더 만들기의
  기본/사용자 이미지 모드, 커진 버튼과 잠금 표시, 아래쪽 차량까지 스크롤·선택.
